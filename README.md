# granki-corpus

Открытый корпус русских текстов для [granki-bench](https://github.com/apantin/granki-bench): общественное достояние и тексты под открытыми лицензиями.

> **Статус: первая публичная часть собрана.** 200 статей и блоговых текстов, 97 групп «источник — автор»; разведочная часть — 127 текстов, подтверждающая — 73. Сбор — 22 ноября 2026 года; очистка `clean-v3`.

2026-11-23: для семи оригиналов совпали URL и SHA-256 очищенного текста с записями Common Crawl `CC-MAIN-2021-04`; у шести период уточнён с неизвестного до `pre-2023`, у производных пар — тот же период. Это подтверждение существования очищенного содержания до 2023 года, а не независимая оценка качества или доказательство отсутствия любой автоматизации. У остальных записей дата публикации сама по себе не исключает поздние правки страницы.

## Зачем

Чтобы оценивать стиль и качество текста, нужна опора из настоящих текстов людей:
- **жанровая норма** — с чем сравнивать частоты штампов, канцелярита и признаков шаблонного текста;
- **шкала голоса** — другие авторы того же жанра и автор сам с собой;
- **эталоны** — человеческие тексты, на которых проверяют метрики и моделей-судей;
- **пары «хорошо — плохо»** для проверки оси качества.

## Что входит

| Источник | Лицензия |
|---|---|
| Классика и публицистика, перешедшие в общественное достояние | общественное достояние |
| Википедия, Викиновости | CC BY-SA 4.0, CC BY 4.0 |
| Открытые научные статьи | CC BY 4.0 |
| Блоги и сайты с явной открытой лицензией | по источнику |
| Официальные тексты | не охраняются авторским правом |
| Русские переводы открытой документации с историей правок | по проекту: CC BY 4.0, CC BY-SA |
| Ответы ru.stackoverflow.com | CC BY-SA |

Жанры — статья и блог, научный и технический текст, нехудожественная книга и научпоп, новости, художественная проза; первым собирается «статья и блог». Кроме текстов — пары «хуже — лучше», сделанные людьми: версии статьи Википедии до и после снятия шаблона о стиле, правки переводов документации, ответы на один вопрос с разным счётом.

Тексты под закрытыми лицензиями в корпус не входят.

## Как устроен

- **`manifest.csv`** — запись на каждый файл:

  | Поле | Что |
  |---|---|
  | `path` | путь к файлу в корпусе |
  | `source_url` | откуда взят текст |
  | `license` | лицензия, найденная на источнике |
  | `attribution` | как указывать авторство |
  | `author` | автор |
  | `genre` | жанр |
  | `period` | период написания |
  | `words` | число слов после очистки |
  | `sha256` | хеш файла |
  | `collected` | дата сбора |

- Файл без записи в манифесте в корпус не входит.
- Очистка одинаковая для всех текстов: без разметки, чужих цитат, подписей и рекламы; кавычки и тире нормализованы.
- У корпуса свои версии и теги; granki-bench записывает версию корпуса в каждом результате.

## Проверка перед коммитом

Включить: `git config core.hooksPath .githooks`. Проверка не пропускает файлы вне разрешённых мест, текст без записи в манифесте или с несовпавшим хешем, запись без лицензии или источника.

## Предложить источник

Откройте issue: ссылка на источник, лицензия и где она указана на источнике, жанр. Тексты без явной открытой лицензии не принимаются.

## Лицензия

Единой лицензии у корпуса нет — см. [LICENSE.md](LICENSE.md): у каждого текста своя лицензия по манифесту, манифест и скрипты — MIT.

## Формат этапа 2

Манифест хранит две версии: `path`/`sha256` — norm, `raw_path`/`raw_sha256` — raw-clean. Обязательны условия сбора `site_terms`, источник для квот `source_id`, `subgenre`, `period_ai`, версия очистки `clean_version`, часть `split` (scouting/confirmation). Соль деления не публикуется. Путь raw-clean явный: его нельзя надёжно восстановить при переносе файлов.

Пары — в `pairs/<источник>/`, единый `pairs/manifest.csv`: обе стороны в двух версиях с хешами, происхождение, лицензия, атрибуция, основание предпочтения, исходный документ, основная/дополнительная единица, часть и назначение. `purpose=neutral-control` требует основания нейтральности; такие пары не означают предпочтения.

Проверка перед коммитом читает итоговый git index целиком и проверяет также удаления. Новый файл без манифеста, отсутствующая сторона, неверный хеш, закрытая лицензия или пустое обязательное поле отклоняются. Тесты: `python3 -m unittest discover -s scripts -p 'test_*.py'`.

## Первый срез: статья и блог

200 текстов из «Теплицы социальных технологий» (CC BY-SA 4.0) и «Завтра» (CC BY 4.0). У каждого — источник, атрибуция, найденная лицензия, условия сбора, две версии очистки и хеши. Квота — не более 10 текстов (5%) на пару «источник — автор». Отбор детерминированный; подтверждающая часть предназначена для проверки без настройки по её результатам.

Это публичная основа для порч и анализа детектора. Жанровая норма по Common Crawl и окончательная проверка качества отбора готовятся в granki-bench. Наличие редакционного источника само по себе не означает отсутствия ошибок в тексте.

## Сбор публичных источников

Код поиска и предварительного извлечения публичных источников открыт в [scripts/collect/](scripts/collect/README.md). HTTP-кэш учитывает robots и Crawl-delay; кандидаты проходят общую очистку granki-bench. Публикация и деление не выполняются сборщиком автоматически.

## Пары контролируемых порч

Срез содержит 1996 пар: 1562 фрагментные и 434 документные. Слабая доза охватывает 200 оригиналов; на детерминированной выборке 30 оригиналов добавлены средняя и сильная дозы и документные контрасты (где они отличаются от фрагмента). Виды `corrupt-v1`: опечатки, пунктуация, типографика, удаление числовой конкретики, перестановки абзацев и предложений, повтор и склейка абзацев. Применимость проверяется для каждого исходника, поэтому число пар по видам различается. Типографика имеет назначение `rules-only`; другие применимые пары — `quality`, с меткой `construction-only`. Диагностические строки не используются как контроль одной оси. Независимая человеческая проверка направления и силы пока не выполнена.

2026-11-23: добавлены 30 фрагментов `quantity-v2` на разных исходниках. Новая [падежно ограниченная числовая порча](https://github.com/apantin/granki-bench/blob/main/docs/quantity-v2.md) не меняет старую corrupt-v1; в происхождении записаны версия, seed и границы фрагмента. Четыре старые пары с дополнительной грамматической ошибкой и один новый norm-контраст, повторивший уже существующий, имеют `purpose=diagnostic-only`. Старые файлы сохранены, диагностические строки не считаются новыми независимыми качественными примерами. Ограничение локального управления не заменяет смысловую проверку и П10.

В манифесте — автор оригинала и источник; `provenance` фиксирует границы фрагмента, вид, дозу, seed, версию и число искусственных изменений. Файл `worse` получен преобразованием фрагмента; он не является опубликованной автором версией. Минимумы набора считаются по исходным документам, а не по числу доз.

60 пар — контроли представления с `purpose=neutral-control`, без предпочтения. У 30 пробельных контролей norm побайтово одинаков. Ещё у 30 календарных контролей norm различается: слово «год» в дате заменено стандартным «г.», числа сохранены. Отдельная агентская проверка 36 разведочных пар в контексте приняла 33 и отвергла три (цитаты и стилистически значимая формула); первые 30 принятых по заранее заданному порядку опубликованы с предварительной меткой. Это не человеческая приёмка и не проверка произвольных смысловых переписываний. Отдельные метрики могут меняться, устойчивость итогового качества проверяется отдельно.
